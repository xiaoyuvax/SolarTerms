# SolarTerms24Net

基于天文算法的**中国农历 / 二十四节气**推算库，C# / .NET 9 实现。

本项目移植自 Python 项目 [Comee/SolarTerms24](https://github.com/Comee/SolarTerms24)，常数表与算法步骤与原版逐行对应，计算结果精确到秒，无需依赖任何星历表文件或第三方天文库。

## 功能

- **二十四节气**：任意年份 24 节气的精确时刻（北京时间），精度与权威万年历一致
- **农历月序推排**：按「以中气定月序」规则排出全年农历月，标注大月（30 天）/ 小月（29 天）
- **闰月推算**：自动识别无中气之月并置闰，正确处理闰月导致的月序重排
- **朔日（新月）时刻**：基于月球运动级数理论计算日月合朔时刻

## 天文算法

| 模块 | 说明 |
|---|---|
| VSOP87 地球运动理论 | 计算太阳黄经 / 黄纬 / 地日距离（E10–E35 周期项级数） |
| 月球运动理论 | 计算月球黄经 / 黄纬 / 距离（M10–M31 级数） |
| 章动 (Nutation) | IAU 章动序列修正 |
| 岁差 (Precession) | 长期岁差修正 |
| 光行差 (Aberration) | 太阳光行差修正 |
| ΔT 修正 | 内置 -4000 ~ 2150 年 ΔT 多项式插值表，实现 TT ↔ UT 换算 |
| 求根 | 割线法迭代求解「太阳视黄经 = k·15°」（节气）与「日月黄经差 = 0」（朔日）的精确时刻 |

## 项目结构

```
SolarTerms24Net.sln
├── SolarTerms24Net/          # 核心类库
│   ├── SolarTerms.cs         # 天文算法 + 农历排月规则（入口：SolarTerms.PaiYue）
│   ├── JDate.cs              # 儒略日 / 公历互转 + ΔT 修正
│   ├── PaiYueItem.cs         # 排月结果数据结构
│   └── Utils.cs              # 配置读取辅助（Py2Cs 移植配套）
└── SolarTermsCmd/            # 控制台示例程序
    └── Program.cs            # 调用 PaiYue 并输出结果
```

## 快速开始

### 环境要求

- [.NET 9 SDK](https://dotnet.microsoft.com/download/dotnet/9.0)

### 运行示例

```bash
git clone https://github.com/xiaoyuvax/SolarTerms.git
cd SolarTerms
dotnet run --project SolarTermsCmd -c Release
```

结果写入 `output/output.txt`，控制台输出 `==============finished!============`。

### 库调用

在你的项目中引用 `SolarTerms24Net` 类库后：

```csharp
using SolarTerms24Net;

// 传入年份字符串，返回全年农历排月 + 节气文本
string result = SolarTerms.PaiYue("2001");
Console.WriteLine(result);
```

## 准确度验证

本库（及所移植的 Python 原版算法）已通过权威数据交叉验证：

- **香港天文台公历-农历对照表**（[官方数据](https://www.hko.gov.hk/en/gts/time/conversion.htm)，依据中国大陆现行农历编制标准）—— 2001/2016/2017/2019–2026 共 11 年：
  - 农历月首（初一）日期 **132/132 全对**
  - 大月 / 小月 **121/121 全对**
  - 闰月标记（含 2001 闰四月、2017 闰六月、2020 闰四月、2023 闰二月、2025 闰六月）**121/121 全对**
  - 节气 / 中气日期 **252/252 全对**
- **精确时刻抽验**（节气时刻 vs 公布值，同为东八区）：差异 ≤ 0.9 分钟（VSOP87 截断级数固有精度）
- 与 Python 原版 `expected.txt` 逐行逐秒一致

### 验证方法与事实记录

**数据来源**：香港天文台《公历与农历日期对照表》年度文本数据（`T{year}e.txt`），其农历与节气数据依据中国大陆现行农历编制标准（紫金山天文台编算体系）编订，与本库输出的时区基准一致（东八区，日界同步，无时区错位）。

**验证程序**：独立 C# 工程逐项比对本库 `PaiYue()` 输出与 HKO 对照表，检查项与结果如下：

| 检查项 | 比对内容 | 样本数 | 结果 |
|---|---|---|---|
| 农历月首日期 | 每月初一公历日期是否与 HKO 初一列表一致 | 132 | **全部一致，0 不一致** |
| 大小月 | 由相邻月首日差（29/30 天）推算的大/小月标记 | 121 | **全部一致，0 不一致** |
| 闰月标记 | 无中气置闰规则判定的闰月 vs HKO 闰月位置 | 121 | **全部一致，0 不一致** |
| 节气/中气日期 | 每行节气与中气（含名称与日期）与 HKO 标注一致 | 252 | **全部一致，0 不一致** |

核对年份：2001、2016、2017、2019、2020、2021、2022、2023、2024、2025、2026（覆盖 5 个闰月年）。

**事实细节**：

- 闰月年验证样本：2001（闰四月）、2017（闰六月）、2020（闰四月）、2023（闰二月）、2025（闰六月），月序重排与大小月全部正确
- 大小月判定依赖月序链完整（14 个朔日），其中上一年腊月的朔时刻在修复前为错误值（`hs[0]` 起点 bug），修复后与 HKO 完全一致
- 626 项总检查（132+121+121+252）**零不一致**

**精确时刻抽验**（10 个节气时刻 vs 公布时刻，均换算至东八区）：

- 春分、立春、夏至、冬至等条目差异 ≤ 0.9 分钟，属 VSOP87 截断级数的固有精度
- 部分网上流传的冬至时刻为 UTC 值，加 8 小时换算后与本库输出逐分钟吻合（如 2023 冬至 03:27 UTC + 8h = 11:27，本库输出 11:27:12）

**附注**：验证过程中确认了 HKO 数据文件的格式细节——列间以 2+ 空格分隔、日期不补零（如 `2016/1/10`）、早期文件 `Lunar month` 小写而新版为 `Lunar Month`、闰月以同一农历月序标签连续出现两次表示（无 "Leap" 字样）。

## 设计说明

- **零依赖**：所有天文常数（VSOP87、章动表、ΔT 表）内嵌于源码，无需星历数据文件
- **忠实移植**：与 Python 原版一一对应，便于逐函数比对验证
- **库 / 壳分离**：`SolarTerms24Net` 为纯计算类库（唯一公开入口 `SolarTerms.PaiYue`），`SolarTermsCmd` 为薄壳入口，方便集成到其他项目
- **时区**：全程东八区（北京时间），日界与显示均按 UTC+8 处理
